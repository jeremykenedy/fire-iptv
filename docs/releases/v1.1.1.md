# fire-iptv 1.1.1

This patch makes Picture-in-Picture opt-in and prepares a versioned Android update. The earlier assetless 1.1.0 release and its tag remain unchanged. The previous published Android APK was 1.0.0.

## Upgrade guide

Update an existing fire-iptv 1.0.0 installation with the signed `fire-iptv.apk` using `adb -s TV_IP:5555 install -r fire-iptv.apk`. Android 7/API 24 or later and a 32-bit or 64-bit ARM processor are required. The package remains `com.jeremykenedy.fireiptv`, with the original production signing certificate. Version 1.1.1 uses Android version code 2.

Keep the existing installation to preserve its profiles, configured sources, favorites and private credentials. This patch adds no database migration or dependency update. A source build from the documentation-only 1.1.0 tag also reports app version 1.0.0/code 1 and follows the same update path. Restart the app after installation and confirm the active profile, sources, favorites, playback and Home/Back behavior.

If Picture-in-Picture is wanted, enable it explicitly in Settings. A previously saved opt-in remains enabled. To roll back, export an application backup first: Android rejects an ordinary version-code downgrade, and uninstalling removes private app data. Do not replace another app's private data to migrate OpenIPTV or OwnTV; they remain separate packages.

## Breaking changes

No package, signing-key, database, provider-parser or Android support-floor change.

An unset Picture-in-Picture preference previously behaved as enabled. It now behaves as disabled, both during startup and after stored preferences load. This affects fresh installs and existing users who never saved a choice. Explicitly saved enabled and disabled values are preserved. Users who want the floating player can turn it on in Settings.

## Major changes

No new catalog, player or provider feature. Custom provider setup and the existing live-only starter behavior are preserved.

## Minor changes and fixes

- Default Picture-in-Picture to off so leaving playback does not opt into a floating window without a saved choice.
- Preserve a saved PiP opt-in or opt-out and keep profile/source selections intact when that setting changes.
- Align Android version metadata with a new patch release instead of replacing the published 1.1.0 tag or relabeling the older APK.

## Verification and release gates

Catalog validation, Flutter analysis and all 269 host tests passed, including a regression that failed against the previous PiP default. The four new checks cover startup defaults, saved choices and persisted toggles without changing the active profile or source.

The original-key signed candidate reports version 1.1.1/code 2 and includes both ARM targets. On an API 34 emulator with no previous installation, first launch and playback worked, About displayed1.1.1, and returning Home from playback produced no pinned Picture-in-Picture task.

On the physical Fire TV AFTDEC012E/API 30, the signed in-place update retained the visible Everyone administrator profile, two playlists,1,323 live channels and226 sports channels. The PiP setting remained unchecked after a force-stop and relaunch. CBS Sports live preview played; returning Home left no pinned task, and the native media session reported inactive with playback state NONE before the app was force-stopped for cleanup. Exact favorite counts were not captured before the update, so no full database preservation claim is made. The test restored the original screensaver selection, protected system settings and foreground protection service.

The exact installed APK SHA-256 is `66605a6dd20a1e5039a1115542626a6027701dd800a0e2d991bcbcf86f7e0294`, 87,759,849 bytes. The original production certificate is unchanged. The three new [physical captures](../screenshots.md) show the current Discover, retained profile/playlists and PiP-off setting. Saved opt-in preservation is covered by host regression tests; it was not toggled on the owner's physical TV.

Publication remains held until final visual review, required source checks, verified remote-primary promotion and public-artifact verification. Native 64-bit physical hardware remains untested. No release publication is claimed by this preparation document.
