# fire-iptv 1.2.0

This release adds live-channel cards for compatible TV launchers. Selecting a card opens the existing player with the selected channel. It does not supply personal Plex, Netflix or Prime Video recommendations.

## Upgrade guide

Update fire-iptv 1.0.0 or 1.1.1 in place with the signed `fire-iptv.apk`:

```bash
adb -s TV_IP:5555 install -r fire-iptv.apk
```

The documentation-only 1.1.0 tag declares application version 1.0.0 and follows the same path. The package remains `com.jeremykenedy.fireiptv`, the production signing certificate is unchanged, and Android version code increases to 3. Android 7/API 24 or newer and a 32-bit or 64-bit ARM processor remain required. Home cards additionally require Android 8/API 26 or newer and a launcher that consumes Android preview programs.

Keep the existing installation to preserve its private database and settings. No database migration, dependency update or provider reconfiguration is required. Open the app after updating to publish cards. In Fire TV UI, enable **Preferences > Appearance > Cards**, and allow **Fire IPTV** in the channel manager if it was hidden. Confirm the active playlist, profile and a selected card's playback.

Before attempting a rollback, export a backup. Android rejects an ordinary downgrade from version code 3; uninstalling removes private app data. Do not uninstall to perform a normal update.

## Breaking changes

None. The package, signer, Android support floor, database, starter sources and saved Picture-in-Picture choices remain unchanged. Cards are an additional launcher integration; existing player routes continue to work.

## Major changes

- Publish up to twelve live channels from the current profile and selected playlist. Favorites precede recently watched channels, followed by the playlist order.
- Apply existing source access, hidden-category and parental restrictions. PIN-protected profiles publish no cards outside the app. Switching profiles or playlists refreshes the source.
- Resolve each selected card against the current database before playback. A deleted or newly restricted channel produces an unavailable message instead of playing stale data.
- Preserve the launcher's source-visibility choice and delete only fire-iptv's stale preview entries. No Watch Next history is fabricated.

The card provider receives channel names, public artwork and a stable ID link. It receives no stream URL or provider credential. The player uses its existing private channel record to open a stream.

## Minor changes and fixes

- Retain pending card links until the database and profile picker are ready.
- Disable Flutter's default URL routing because native card links are routed after those checks. This fixes the cold-start "Page Not Found" regression found during remote-control testing.
- Query current channel history when choosing recently watched cards.
- Keep card publishing off unsupported devices and handle unavailable TV providers without blocking the player.

## Limitations

The launcher controls presentation. Fire TV UI currently selects one program per preview channel for its featured rotation; twelve published programs do not imply twelve visible hero cards. A launcher can hide the entire source independently.

Publishing happens while opening or using the player, including profile and playlist changes and return from playback. There is no background polling service. Stream availability and guide coverage depend on the service and network. Physical 64-bit hardware remains untested.

Movies and series still require a provider supplied by the owner. These live cards do not create personal recommendations for separate streaming applications.
